FOOD DELIVERY DOCKER COMPOSE — LAUNCH STEPS
===========================================

Prerequisites
-------------
1. Install and start Docker Desktop.
2. Open PowerShell in the FoodDelivery.Api repository folder:
   D:\projects\food-delivery\FoodDelivery.Api
3. Confirm that .env exists in this folder. It contains the local service
   passwords and should not be shared or committed to Git.

Start the services
------------------
Run these commands from the repository folder:

   docker compose config --quiet
   docker compose up -d
   docker compose ps

The first start downloads the container images and may take a few minutes.
Wait until PostgreSQL and Kafka show as healthy before connecting to them.

Open the services
-----------------
PostgreSQL:  localhost:5432
pgAdmin:     http://localhost:5050
Kafka:       localhost:9094
Redis:       localhost:6379
Prometheus:  http://localhost:9090
Grafana:     http://localhost:3000
Keycloak:    http://localhost:8080

Use the matching values in .env to sign in to pgAdmin, Grafana, and Keycloak.
For pgAdmin, add a server with host "postgres", port 5432, database
"fooddelivery", and username "fooddelivery". Use FOODDELIVERY_DB_PASSWORD
from .env as its password.

Useful commands
---------------
Show service status:
   docker compose ps

Follow logs for all services:
   docker compose logs -f

Follow logs for one service (replace SERVICE with e.g. postgres or keycloak):
   docker compose logs -f SERVICE

Stop services and preserve their data:
   docker compose down

Start them again later:
   docker compose up -d

WARNING: Remove containers and all stored service data:
   docker compose down -v

The stack is configured for local development. Keycloak runs in development
mode and Kafka uses unauthenticated plaintext listeners; do not expose these
services to a public network.

Run the API with PostgreSQL
---------------------------
The API connection string is stored outside the repository in .NET user
secrets. From the repository folder, run this once (or whenever the app DB
password changes):

   dotnet user-secrets init
   $dbPassword = (Get-Content .env | Where-Object { $_ -match '^FOODDELIVERY_DB_PASSWORD=' }) -replace '^FOODDELIVERY_DB_PASSWORD=', ''
   dotnet user-secrets set 'ConnectionStrings:FoodDelivery' "Host=localhost;Port=5432;Database=fooddelivery;Username=fooddelivery;Password=$dbPassword"
   $env:ASPNETCORE_ENVIRONMENT = 'Development'
   dotnet ef database update
   dotnet run

API endpoints
-------------
Look up a restaurant:
   GET http://localhost:5115/api/restaurants/1

Get the restaurant managed by an owner:
   GET http://localhost:5115/api/owners/1/restaurant

Change capacity (body: {"capacity": 80}):
   PUT http://localhost:5115/api/restaurants/1/capacity

Change operating days and days off (Monday=1 through Sunday=7):
   PUT http://localhost:5115/api/restaurants/1/days
   {"operatingDayIds":[1,2,3,4,5],"offDayIds":[6,7]}

Change opening hours (24-hour local times):
   PUT http://localhost:5115/api/restaurants/1/opening-hours
   {"opensAt":"08:00","closesAt":"22:00"}

Restaurant chefs and candidatures
---------------------------------
List chefs (summary fields):
   GET http://localhost:5115/api/restaurants/1/chefs

Get one chef's full details:
   GET http://localhost:5115/api/restaurants/1/chefs/3

List candidatures received by the restaurant, including their status:
   GET http://localhost:5115/api/restaurants/1/candidatures

Create a candidature (body: {"chefId": 3, "salary": 2500}):
   POST http://localhost:5115/api/restaurants/1/candidatures

Get one candidature:
   GET http://localhost:5115/api/restaurants/1/candidatures/7

Get every chef field for the chef who made a candidature:
   GET http://localhost:5115/api/restaurants/1/candidatures/7/chef

Refuse a pending candidature:
   PUT http://localhost:5115/api/restaurants/1/candidatures/7/refuse

Assign an existing, unassigned chef to the restaurant:
   POST http://localhost:5115/api/restaurants/1/chefs/3

Refusing a candidature that is no longer pending, or assigning a chef who
already belongs to another restaurant, returns HTTP 409 Conflict. IDs in
these examples must refer to existing database records.
